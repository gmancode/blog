# Обновление дизайна блога

## ⚠️ Сначала — безопасность

В старом `djangoProject/settings.py` в открытом виде лежали реальный пароль от Gmail
(`EMAIL_HOST_PASSWORD`) и Django `SECRET_KEY`, закоммиченные в публичный репозиторий.
До переноса изменений:

1. Смените пароль этого Gmail-аккаунта (лучше — используйте app password).
2. Сгенерируйте новый `SECRET_KEY`.
3. Проверьте, что секреты не «висят» в истории git (при необходимости — перезалейте
   репозиторий или очистите историю, например через `git filter-repo`).

## Что изменено

**Дизайн** — полностью переписаны шаблоны и CSS:
- `blog/static/css/blog.css` — новая дизайн-система: карточки, тени, градиентный
  сине-фиолетовый акцент, шрифты Inter/Manrope, светлая и тёмная тема (переключатель
  в шапке + автоопределение по системным настройкам).
- `blog/templates/blog/base.html`, `.../post/list.html`, `.../post/detail.html`,
  `.../post/share.html`, `.../pagination.html` — адаптивная сетка вместо старых
  float-колонок, карточки постов, теги-пилюли, аватары-инициалы, современные формы.

**Технические правки:**
- `blog/views.py` — убрана дублирующаяся функция `post_detail`, исправлена опечатка
  в письме share-формы.
- `djangoProject/settings.py` — секреты вынесены в переменные окружения (см.
  `.env.example`), убрана устаревшая настройка `USE_L10N` (удалена в Django 4.0+),
  добавлены `STATIC_ROOT`/`STATICFILES_DIRS`.
- `requirements.txt` — обновлён на Django 5.2 (текущий LTS, поддержка до апреля 2028)
  и Python 3.10+ вместо Django 3.2 / Python 3.8 (оба EOL).
- Добавлен `.gitignore`, чтобы `.env`, `venv/` и `db.sqlite3` больше не попадали в git.

## Как применить

Это не весь проект, а только изменённые/новые файлы поверх вашего репозитория
(`blog/`, `djangoProject/`, `requirements.txt`, `.gitignore`, `.env.example`).
`db.sqlite3`, `venv/`, `manage.py` не менялись по содержанию — `manage.py` включён
для полноты, остальное трогать не нужно.

```bash
# 1. Скопируйте файлы из этого архива в свой репозиторий (замените существующие).

# 2. Создайте .env на основе примера и впишите новые секреты:
cp .env.example .env

# 3. Обновите зависимости:
pip install -r requirements.txt

# 4. Проверьте, что всё поднимается:
python manage.py migrate
python manage.py runserver
```

Я локально прогнал `python manage.py check`, применил миграции и поднял dev-сервер
на вашей исходной базе с постами и комментариями — страницы `/blog/` и страница поста
отдают 200 и корректно рендерят карточки, теги и комментарии с новым дизайном.
